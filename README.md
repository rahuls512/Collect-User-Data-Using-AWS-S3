# Collect User Data Using AWS S3

A small static web page with a form. The user enters a **Name** and **Surname**, clicks **Submit**, and the data is saved as a JSON file in an **AWS S3** bucket.

## How It Works

1. The user opens the website hosted on S3.
2. The user fills in the form and clicks Submit.
3. The page asks **Amazon Cognito** for temporary credentials.
4. Using those credentials, the page uploads a JSON file to the `submissions/` folder in S3.

**Why Cognito?** No AWS access keys are ever stored in the code. Cognito gives short-lived, safe credentials.
**Why esbuild?** The AWS SDK is built for Node.js. esbuild bundles it with our code into one `bundle.js` that runs in the browser.

## Tech Stack

- AWS S3 (static website hosting + file storage)
- Amazon Cognito Identity Pool (guest access)
- AWS IAM (least-privilege role)
- AWS SDK for JavaScript v3
- esbuild
- HTML, CSS, JavaScript

## Quick Setup

**1. Install packages**
```bash
npm init -y
npm install @aws-sdk/client-s3 @aws-sdk/credential-providers
npm install @aws-sdk/client-cognito-identity @aws-sdk/credential-provider-cognito-identity
npm install --save-dev esbuild
```

**2. AWS setup (details in the PDF)**
- Create an S3 bucket and enable **static website hosting**.
- Add a bucket policy so only `index.html` and `bundle.js` are public.
- Add a CORS rule that allows only your website URL.
- Create a Cognito **Identity Pool** with guest access and copy the Pool ID.
- Give the guest IAM role only `s3:PutObject` on `submissions/*`.

**3. Configure `app.js`**
```js
const REGION = "ap-south-1";
const BUCKET = "YOUR-BUCKET";
const IDENTITY_POOL_ID = "YOUR-IDENTITY-POOL-ID";
```

**4. Build the bundle**
```bash
npx esbuild app.js --bundle --platform=browser --format=iife --outfile=bundle.js
```
Run this again every time you change `app.js`.

**5. Deploy**
Upload only `index.html` and `bundle.js` to the bucket. Open the S3 website endpoint in your browser.

## Security

- No AWS access keys in the code.
- Temporary credentials come from Cognito.
- Only `index.html` and `bundle.js` are public.
- Submitted JSON files are private (Access Denied if opened by URL).
- Guest role can only upload to `submissions/*`. It cannot read, list, or delete.
- CORS allows only the website origin.

## Common Problems

| Problem | Fix |
|---|---|
| CORS error | Check the CORS origin matches your website URL exactly (http, no trailing slash) |
| Access Denied on upload | Check the IAM policy bucket name and `submissions/*` path |
| Cognito error | Check Pool ID and region in `app.js`, rebuild, re-upload |
| Old behavior on page | Rebuild `bundle.js` and upload it again |
| 403 on website | Check Block Public Access settings and bucket policy |

Press **F12 → Console** in the browser to see the real error.
